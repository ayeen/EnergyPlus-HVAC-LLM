Automated HVAC System Design using Multi-Agent Large Language Models with RAG and Fine-Tuning

Figure 1. Multi-Agent System Architecture
Figure 1. Multi-agent system architecture for automated HVAC generation. The pipeline consists of three specialized agents: Agent 1 (VRF Generator) transforms natural language requests into HVACTemplate objects using a fine-tuned Mistral-7B model; Agent 2 (Validation Orchestrator) performs syntax validation, template expansion, and EnergyPlus simulation; Agent 3 (Iterative Debugger) analyzes errors and applies corrections with a maximum of 3 iterations to ensure bounded execution time.
Figure 2. Agent 1: VRF Generator Workflow
Figure 2. Agent 1 workflow showing the iterative generation strategy. The process begins with user input (natural language request, zone list, building context) which is enhanced with RAG-retrieved knowledge (field specifications, design rules, similar examples). The fine-tuned Mistral-7B model generates HVACTemplate objects in three sequential steps: System:VRF with all 42 fields, Zone:VRF for each thermal zone, and corresponding Thermostats with setpoint schedules.
Figure 3. Agent 2: Four-Stage Validation Pipeline
Figure 3. Four-stage validation pipeline in Agent 2. Stage 1 performs IDD (Input Data Dictionary) compliance checking to validate object types and required fields against the EnergyPlus schema. Stage 2 uses Eppy library for syntax validation and cross-object reference checking. Stage 3 runs the ExpandObjects preprocessor to transform HVACTemplate objects into detailed simulation objects. Stage 4 executes the full EnergyPlus simulation and parses the error log (eplusout.err) to classify errors by severity.
Figure 4. Agent 3: Iterative Correction Workflow
Figure 4. Agent 3 iterative correction workflow. Upon receiving error messages from Agent 2, Agent 3 queries the RAG knowledge base for similar error patterns. If similarity exceeds 77%, a cached fix is applied directly without LLM generation. Otherwise, the fine-tuned Mistral-7B model generates a JSON fix specification containing the object type, field to change, and new value. The correction is applied using Eppy, and the IDF is re-submitted for simulation. This process iterates up to 3 times to ensure bounded execution time.
Figure 5. RAG Knowledge Base Architecture
Figure 5. RAG knowledge base architecture using ChromaDB vector database. The knowledge base contains 718+ documents organized into specialized collections: field_specs (42 VRF field specifications), error_patterns (50+ historical error-fix pairs), design_rules (HVAC best practices), field_dependencies (25 inter-field validation rules), and fix_procedures (step-by-step correction guides). Documents are embedded using BAAI/bge-small-en-v1.5 (384 dimensions) with cosine similarity search. Agent 1 primarily queries field specifications and design rules, while Agent 3 focuses on error patterns and fix procedures.
Figure 6. LoRA Fine-Tuning Approach
Figure 6. LoRA (Low-Rank Adaptation) fine-tuning approach. The base Mistral-7B model remains frozen while small adapter matrices (A and B) are trained on domain-specific data. Only ~0.1% of parameters are updated, enabling efficient training in approximately 4 GPU hours. The adapters target attention projection layers (q, k, v, o). For inference, 4-bit quantization (QLoRA with NF4) reduces memory requirements to ~6GB, enabling deployment on consumer GPUs. Two separate adapters were trained: Agent 1 for VRF generation (500+ examples) and Agent 3 for error correction (200+ error-fix pairs).
Figure 7. Success Rate Comparison: Fine-tuned vs. Pre-trained Models
Figure 7. Success rate comparison between fine-tuned Mistral-7B and pre-trained models across five test cases (1-20 zones). Fine-tuned models achieve 80% first-try success and 100% final success through Agent 3 correction. Pre-trained models with in-context examples achieve only 20% success, while pre-trained models without examples fail completely (0%). The 80% improvement demonstrates that domain-specific fine-tuning is essential for specialized EnergyPlus HVAC generation tasks.
Figure 8. Scalability Analysis: Output Quality vs. Zone Count
Figure 8. Scalability analysis showing output quality versus zone count. Fine-tuned Mistral-7B maintains consistent 100% quality across all scales from 1 to 20 zones, demonstrating no degradation with increasing complexity. In contrast, pre-trained models with in-context examples show progressive quality decline: ~100% at 1 zone, ~85% at 2 zones, ~65% at 4 zones, ~35% at 10 zones, and complete failure (~8%) at 20 zones. The breaking point at 20 zones indicates fundamental limitations of in-context learning for complex, scale-dependent generation tasks.
Figure 9. RAG Contribution Analysis (Ablation Study)
Figure 9. RAG contribution analysis through ablation study comparing four configurations: Fine-tuned+RAG (100% success), Fine-tuned only (95% success), Pre-trained+RAG (20% success), and Pre-trained only (0% success). RAG provides a modest +5% improvement for fine-tuned models by enhancing edge case handling through retrieved field specifications and error patterns. However, RAG cannot compensate for the lack of domain-specific training in pre-trained models, demonstrating that RAG enhances but cannot replace fine-tuning.
Figure 10. Multi-Agent Synergy Effect
Figure 10. Multi-agent synergy effect demonstrating how the combination of Agent 1 (VRF Generator) and Agent 3 (Error Corrector) achieves 100% final success from 80% first-try success. Agent 1's fine-tuned Mistral-7B achieves 80% first-try success across five test cases (1-20 zones). For the remaining 20% of cases where initial generation fails, Agent 3's error correction mechanism achieves 100% fix success rate within the 3-iteration limit. This generate-validate-correct paradigm provides robustness without requiring any single component to be perfect, enabling production-ready reliability for automated HVAC system design.
